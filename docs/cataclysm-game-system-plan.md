# Gitagotchi 대격변 업데이트 게임 시스템 상세 기획서

## 0. 문서 목적

이 문서는 Gitagotchi 대격변 업데이트의 게임 시스템을 상세하게 정의합니다. 여기서 게임 시스템은 펫의 외형이나 진화 규칙이 아니라, 사용자의 개발 행동이 어떤 목표, 보상, 도전, 반복 루프로 변환되는지를 의미합니다.

Gitagotchi는 독립 실행형 게임이 아닙니다. 사용자는 VS Code 안에서 개발을 계속해야 하고, Gitagotchi는 그 개발 행동 위에 게임적 의미를 얹어야 합니다. 따라서 시스템 설계의 핵심은 "사용자가 따로 플레이하지 않아도 진행되는 게임"입니다.

이 문서가 다루는 범위는 다음과 같습니다.

- 핵심 게임 루프
- 경험치와 성장 보상
- 오늘의 퀘스트
- 장식과 수집
- 직업 빌드
- 레이드 보스
- 콤보
- 시즌 진행
- 연구소와 별 조각
- 마스터리
- 주간 회고
- 환생과 별
- 로그와 성취 피드백
- 밸런스 원칙
- 구현 매핑과 테스트 기준

## 1. 게임 시스템 비전

Gitagotchi의 게임 시스템은 개발자의 작업을 방해하지 않아야 합니다. 사용자가 매일 하는 개발 행동이 자연스럽게 게임 진행으로 바뀌어야 하며, 게임을 하기 위해 별도의 반복 클릭이나 시간 소모를 요구해서는 안 됩니다.

핵심 비전은 다음과 같습니다.

> 개발자는 코드를 작성하고, Gitagotchi는 그 행동을 성장, 퀘스트, 레이드, 시즌, 환생의 서사로 번역합니다.

이 시스템에서 사용자는 세 가지 감정을 느껴야 합니다.

- 오늘 할 목표가 보입니다.
- 내 작업이 구체적인 진행률로 바뀝니다.
- 오래 사용할수록 사라지지 않는 기록이 쌓입니다.

## 2. 전체 게임 루프

### 2.1 기본 루프

기본 루프는 다음 순서로 작동합니다.

1. 사용자가 개발 행동을 합니다.
2. 이벤트가 성장 엔진으로 들어갑니다.
3. 기본 경험치와 상태 변화가 계산됩니다.
4. 스타일 점수가 누적됩니다.
5. 스킬 보너스가 적용됩니다.
6. 오늘의 퀘스트 진행이 적용됩니다.
7. 엔드게임 진행이 적용됩니다.
8. 레벨, 상태, 로그, 보상이 갱신됩니다.
9. UI에서 최신 성취가 표시됩니다.

이 흐름은 사용자에게 노출되는 게임 조작보다 내부 계산에 가깝습니다. 사용자는 복잡한 계산을 알 필요 없이 결과만 이해하면 됩니다.

### 2.2 단기 루프

단기 루프는 하루 단위입니다.

- 오늘의 퀘스트를 선택합니다.
- 개발 행동으로 퀘스트를 진행합니다.
- 완료하면 경험치와 장식을 얻습니다.
- 최신 성취 배너가 뜹니다.

단기 루프의 목적은 매일 앱을 열 이유를 만드는 것입니다.

### 2.3 중기 루프

중기 루프는 며칠에서 몇 주 단위입니다.

- 레이드 보스를 시작합니다.
- 매일 개발 행동으로 보스 HP를 줄입니다.
- 콤보와 직업 보너스를 통해 효율을 높입니다.
- 시즌 진행률을 쌓습니다.
- 주간 회고를 확인합니다.

중기 루프의 목적은 반복 사용자가 "이번 주의 목표"를 갖게 하는 것입니다.

### 2.4 장기 루프

장기 루프는 고레벨 사용자 대상입니다.

- 마스터리 랭크를 올립니다.
- 별 조각을 제작합니다.
- 궁극 단계와 30레벨 이후 환생합니다.
- 별을 얻고 다시 성장합니다.
- 더 많은 별과 격파 기록을 쌓습니다.

장기 루프의 목적은 레벨업 이후에도 게임이 끝나지 않게 하는 것입니다.

## 3. 입력 이벤트 설계

### 3.1 이벤트 유형

현재 게임 시스템은 다음 개발 이벤트를 기반으로 작동합니다.

- diff 이벤트
- commit 이벤트
- diagnostics 이벤트
- idleTick 이벤트

각 이벤트는 게임 시스템에서 다른 의미를 가집니다.

diff 이벤트:

- 코드 작성과 변경을 의미합니다.
- 기본 경험치의 주요 원천입니다.
- 파일 유형에 따라 문서, 테스트, 설정 작업으로 해석됩니다.
- 삭제가 추가보다 많으면 정리 또는 리팩터링으로 해석됩니다.

commit 이벤트:

- 작업 완료와 출하를 의미합니다.
- 에너지와 건강 회복에 중요합니다.
- 릴리즈형 플레이와 레이드 피해량에 강하게 연결됩니다.

diagnostics 이벤트:

- 문제 해결 또는 문제 증가를 의미합니다.
- 문제 해결은 디버깅 스타일과 레이드 피해량에 연결됩니다.
- 문제 증가도 상태 변화의 근거가 될 수 있습니다.

idleTick 이벤트:

- 장시간 미사용과 복귀를 표현합니다.
- 방치 페널티와 복귀 회복을 담당합니다.
- 생산성 압박이 아니라 펫 케어 감각을 만드는 장치입니다.

### 3.2 이벤트 해석 원칙

게임 시스템은 개발 행동을 최대한 긍정적으로 해석해야 합니다. 단, 모든 행동을 똑같이 보상하면 시스템이 무의미해집니다. 따라서 보상은 행동의 성격을 구분하되, 사용자를 처벌하는 방식은 피합니다.

원칙:

- 코드 작성은 성장의 기본값입니다.
- 커밋은 완료감을 줍니다.
- 문제 해결은 건강과 디버깅 보상을 줍니다.
- 문서와 테스트는 장기 품질 보상을 줍니다.
- 리팩터링은 정리 계열 성장을 줍니다.
- 방치는 약한 상태 변화로 표현하되 복귀 기회를 제공합니다.

## 4. 경험치 시스템

### 4.1 역할

경험치는 가장 기본적인 성장 자원입니다. 사용자는 경험치를 통해 레벨을 올리고, 레벨은 진화와 환생 조건에 연결됩니다.

경험치는 다음 시스템의 기반입니다.

- 레벨업
- 진화 단계
- 시즌 진행
- 마스터리 랭크
- 레이드 보상
- 퀘스트 보상
- 연구소 재료 사용

### 4.2 레벨 곡선

현재 경험치 요구량은 특정 레벨의 고정 기준점과 스케일 공식을 함께 사용합니다.

기준점:

- 1레벨: 80
- 2레벨: 100
- 5레벨: 220
- 10레벨: 420
- 15레벨: 700
- 20레벨: 1050
- 30레벨: 2000
- 50레벨: 5000
- 90레벨: 15000

기획 의도:

- 초반은 빠르게 성장해야 합니다.
- 5레벨과 15레벨은 진화 체감 지점입니다.
- 30레벨은 환생 조건과 연결되는 장기 목표입니다.
- 50레벨 이후는 고레벨 사용자용 장기 성장입니다.

### 4.3 경험치 보상 원칙

경험치 보상은 행동의 난이도와 의미에 비례해야 합니다.

보상 강도:

- 일반 diff: 낮음에서 중간
- 커밋: 중간
- 퀘스트 완료: 중간
- 콤보 발견: 중간에서 높음
- 레이드 타격: 낮음에서 중간
- 레이드 클리어: 높음
- 환생: 경험치 보상보다 영구 별 보상

### 4.4 과보상 방지

개발 도구 확장에서 보상 시스템은 쉽게 악용될 수 있습니다. 따라서 보상은 다음 방식으로 제어합니다.

- 일일 퀘스트는 하루 단위로 제한합니다.
- 콤보는 최초 발견 보상 중심으로 설계합니다.
- 레이드 피해는 행동 유형에 따라 계산하되 보너스 경험치에 상한을 둡니다.
- 시즌 보상은 milestone 기반으로 제한합니다.

## 5. 상태 시스템

### 5.1 상태 항목

Gitagotchi는 다음 상태를 가집니다.

- 기분
- 배고픔
- 에너지
- 건강
- 생명 상태

UI에서는 배고픔을 직접 보여주는 대신 포만감으로 보여줍니다. 포만감은 `100 - hunger`입니다.

### 5.2 상태의 게임적 의미

기분:

- 사용자가 긍정적인 행동을 할 때 상승합니다.
- 스킬과 성장 분위기에 영향을 줍니다.
- 낮으면 슬픈 상태로 보일 수 있습니다.

배고픔:

- 방치와 시간 경과를 표현합니다.
- 높아질수록 위험합니다.
- UI에서는 포만감 감소로 보여줍니다.

에너지:

- 펫의 활동 가능성을 표현합니다.
- 낮으면 수면 상태에 가까워집니다.

건강:

- 생존과 위험 상태의 핵심입니다.
- 0이 되면 사망 상태입니다.

생명 상태:

- alive
- sleeping
- critical
- dead

### 5.3 상태 변화 원칙

상태 시스템은 사용자를 꾸짖는 도구가 아니어야 합니다. 방치로 상태가 나빠질 수 있지만, 복귀 행동으로 회복할 수 있어야 합니다.

좋은 상태 설계:

- 개발 행동을 통해 자연스럽게 회복됩니다.
- 위험 상태가 명확히 표시됩니다.
- 사망 상태에서도 부활 루트가 있습니다.

나쁜 상태 설계:

- 장시간 사용하지 않았다는 이유로 과도한 손실을 줍니다.
- 복귀 사용자가 죄책감을 느끼게 합니다.
- 회복 방법이 불명확합니다.

## 6. 오늘의 퀘스트 시스템

### 6.1 역할

오늘의 퀘스트는 매일 접속 동기를 만드는 시스템입니다. 사용자는 하루에 하나의 목표를 선택하고, 개발 행동을 통해 완료합니다.

### 6.2 퀘스트 제공 방식

매일 3개의 퀘스트가 제공됩니다. 제공 목록은 날짜 기반으로 순환합니다.

현재 퀘스트 풀:

- 버그 사냥
- 정리의 날
- 현장 가이드
- 출하 준비
- 균형 훈련

### 6.3 퀘스트별 설계

버그 사냥:

- 목표: 진단 문제 3개 해결
- 보상: 경험치 35, 기분 6, 버그 렌즈
- 의도: 디버깅 행동을 보상합니다.

정리의 날:

- 목표: 삭제가 추가보다 많은 정리 diff 1회
- 보상: 경험치 30, 기분 5, 정리 리본
- 의도: 리팩터링과 정리 행동을 보상합니다.

현장 가이드:

- 목표: README, 문서, 노트 수정
- 보상: 경험치 28, 기분 5, 책갈피 망토
- 의도: 문서화를 보상합니다.

출하 준비:

- 목표: 커밋 1회 완료
- 보상: 경험치 32, 기분 5, 커밋 메달
- 의도: 작업 완료와 출하를 보상합니다.

균형 훈련:

- 목표: 현재 가장 낮은 스타일 점수 상승
- 보상: 경험치 40, 기분 7, 균형 후광
- 의도: 편향된 플레이를 완화하고 다양한 개발 행동을 유도합니다.

### 6.4 퀘스트 제한

퀘스트는 하루의 집중 목표여야 합니다. 따라서 다음 제한이 필요합니다.

- 하루가 바뀌면 새 퀘스트 목록이 생성됩니다.
- 진행 중인 퀘스트는 중간 변경하지 않습니다.
- 완료한 퀘스트는 같은 날 다시 보상하지 않습니다.
- 사망 상태에서는 퀘스트가 진행되지 않습니다.

### 6.5 퀘스트 UX 목표

사용자는 퀘스트를 보고 다음 질문에 답할 수 있어야 합니다.

- 오늘 무엇을 하면 되는가?
- 얼마나 남았는가?
- 완료하면 무엇을 얻는가?

## 7. 장식과 수집 시스템

### 7.1 역할

장식은 사용자의 행동 기록을 수집 가능한 형태로 바꾸는 시스템입니다. 경험치는 사라지거나 소비될 수 있지만, 장식은 "내가 이 행동을 달성했다"는 증거로 남습니다.

### 7.2 장식 종류

퀘스트 장식:

- 버그 렌즈
- 정리 리본
- 책갈피 망토
- 커밋 메달
- 균형 후광

레이드 장식:

- 레거시 왕관
- 디버그 왕관
- 릴리즈 배너
- 의존성 부적

엔드게임 장식:

- 별 조각
- 시즌 유물

### 7.3 장식 설계 원칙

장식은 단순히 보상 목록이 아니라 사용자의 플레이 히스토리입니다.

원칙:

- 장식 이름은 어떤 행동으로 얻었는지 암시해야 합니다.
- 장식은 중복 획득보다 최초 획득의 의미가 커야 합니다.
- 장식은 향후 컬렉션 화면으로 확장 가능해야 합니다.
- 레이드 장식은 퀘스트 장식보다 희귀하게 느껴져야 합니다.

## 8. 직업 빌드 시스템

### 8.1 역할

직업 빌드는 고레벨 사용자의 자기 표현과 최적화를 담당합니다. 사용자는 자신의 개발 스타일에 맞는 직업을 선택하고, 해당 스타일 행동에서 보너스를 얻습니다.

### 8.2 직업 목록

릴리즈 마스터:

- 선호 스타일: builder
- 의미: 커밋과 기능 출하 중심

코드 가드너:

- 선호 스타일: cleaner
- 의미: 정리와 리팩터링 중심

버그 트래커:

- 선호 스타일: debugger
- 의미: 문제 해결 중심

아카이비스트:

- 선호 스타일: scholar
- 의미: 문서와 지식 정리 중심

밸런스 아키텍트:

- 선호 스타일: streak
- 의미: 약한 스타일을 끌어올리는 균형 중심

### 8.3 직업 보너스

현재 직업 보너스는 선택한 직업의 선호 스타일이 성장했을 때 적용됩니다.

보상:

- 경험치 6 + 보유 별 수
- 기분 1

기획 의도:

- 직업 선택이 실제 진행에 영향을 줍니다.
- 별 보유량이 직업 보너스에 연결되어 환생 가치를 높입니다.
- 보너스 수치는 너무 크지 않아 기본 개발 행동을 압도하지 않습니다.

### 8.4 향후 확장

직업 시스템은 다음 방향으로 확장할 수 있습니다.

- 직업별 레이드 상성
- 직업별 전용 퀘스트
- 직업 레벨
- 직업 변경 비용
- 직업별 장식

## 9. 콤보 시스템

### 9.1 역할

콤보는 특정 개발 행동 순서를 발견했을 때 보상을 주는 시스템입니다. 사용자는 단순 반복보다 좋은 작업 흐름을 만들었을 때 추가 보상을 얻습니다.

### 9.2 이벤트 토큰

게임 시스템은 개발 행동을 내부 토큰으로 변환합니다.

예시:

- diagnosticsDown
- commit
- cleanupDiff
- docsDiff
- testDiff
- codeDiff

이 토큰의 최근 흐름을 보고 콤보를 판정합니다.

### 9.3 현재 콤보

스태빌라이저:

- 조건: 테스트 변경, 문제 해결, 커밋 흐름
- 의미: 안정화 작업을 완성한 흐름

정리 완료:

- 조건: 정리 diff, 문서 변경, 커밋 흐름
- 의미: 코드 정리와 문서화를 함께 마무리한 흐름

스펙 주도:

- 조건: 문서 변경, 코드 변경, 커밋 흐름
- 의미: 문서나 사양을 기반으로 구현한 흐름

### 9.4 콤보 보상

콤보 최초 발견 보상:

- 경험치 45
- 기분 5

기획 의도:

- 좋은 작업 순서를 발견하는 재미를 줍니다.
- 무한 반복 파밍을 막기 위해 최초 발견 중심으로 설계합니다.
- 고레벨 사용자에게 숨은 성취를 제공합니다.

## 10. 레이드 시스템

### 10.1 역할

레이드는 고레벨 사용자의 주요 공략 콘텐츠입니다. 레이드는 단순 경험치 누적을 보스 HP 감소라는 명확한 목표로 바꿉니다.

### 10.2 레이드 시작

사용자는 진행 중인 레이드가 없을 때 보스를 선택해 시작합니다.

규칙:

- 한 번에 하나의 activeRaid만 유지합니다.
- 보스는 시작 시 최대 HP로 생성됩니다.
- 시작 시각이 기록됩니다.

### 10.3 보스 목록

레거시 드래곤:

- 최대 HP: 240
- 보상 장식: 레거시 왕관
- 주요 피해원: 삭제가 추가보다 많은 정리 diff
- 의미: 기술 부채와 오래된 구조를 공략합니다.

버그 로드:

- 최대 HP: 220
- 보상 장식: 디버그 왕관
- 주요 피해원: 진단 문제 해결
- 의미: 버그와 회귀를 공략합니다.

릴리즈 골렘:

- 최대 HP: 260
- 보상 장식: 릴리즈 배너
- 주요 피해원: 커밋, 테스트 변경
- 의미: 배포와 마감의 압박을 공략합니다.

의존성 망령:

- 최대 HP: 210
- 보상 장식: 의존성 부적
- 주요 피해원: 설정 파일, 패키지 파일 변경
- 의미: 환경과 의존성 문제를 공략합니다.

### 10.4 피해 계산 원칙

피해량은 다음 요소로 구성됩니다.

- 기본 성장 경험치 일부
- 보스별 선호 행동 보너스
- 관련 스타일 점수 보너스

이 구조는 사용자가 어떤 보스를 공략하느냐에 따라 유리한 행동이 달라지게 만듭니다.

### 10.5 레이드 타격 보상

피해가 0보다 크면 레이드 타격 보상을 줍니다.

보상:

- 피해량에 비례한 경험치
- 최대 20 EXP

기획 의도:

- 보스를 때릴 때마다 작은 보상이 있습니다.
- 하지만 타격 보상이 기본 성장이나 클리어 보상을 압도하지 않습니다.

### 10.6 레이드 클리어 보상

보스 HP가 0이 되면 클리어 처리합니다.

보상:

- 경험치 80
- 기분 10
- 보스별 장식
- 격파 기록 추가

규칙:

- 이미 격파한 보스는 격파 기록 중복 추가를 피합니다.
- 장식도 중복 추가하지 않습니다.
- 클리어 후 activeRaid는 비워집니다.

### 10.7 레이드 밸런스

레이드는 하루 안에 너무 쉽게 끝나면 장기 목표가 되지 않습니다. 반대로 너무 오래 걸리면 진척감을 잃습니다.

권장 체감:

- 초중반 사용자: 며칠에 걸쳐 클리어
- 고레벨 사용자: 행동 스타일이 맞으면 빠르게 클리어
- 잘못된 보스 선택: 느리지만 진행 가능

## 11. 시즌 시스템

### 11.1 역할

시즌은 기간 기반 진행도를 제공합니다. 사용자는 매일의 행동이 시즌 진행률로 누적된다는 느낌을 받습니다.

### 11.2 현재 시즌

현재 시즌 ID:

- breakpointRuins

시즌 목표:

- 500 progress

시즌 보상:

- 시즌 유물

### 11.3 진행 계산

시즌 진행도는 다음을 합산합니다.

- 기본 성장 경험치
- 직업 보너스
- 콤보 보너스
- 레이드 보너스

기획 의도:

- 거의 모든 긍정적 개발 행동이 시즌에 기여합니다.
- 고레벨 시스템 보너스도 시즌 진행에 영향을 줍니다.
- 시즌은 별도 조작 없이 자연스럽게 진행됩니다.

### 11.4 milestone 보상

현재 milestone은 500입니다. 500에 도달하면 시즌 유물을 지급합니다.

원칙:

- milestone은 중복 지급하지 않습니다.
- 향후 100, 250, 500 같은 다단계 보상으로 확장할 수 있습니다.
- 시즌 보상은 장기 사용의 증거여야 합니다.

## 12. 연구소와 별 조각 시스템

### 12.1 역할

연구소는 경험치를 장기 자원으로 전환하는 시스템입니다. 사용자는 레벨업에만 경험치를 쓰는 것이 아니라, 별 조각을 제작해 엔드게임 목표를 준비할 수 있습니다.

### 12.2 별 조각 제작

현재 규칙:

- 현재 EXP가 250 이상이어야 합니다.
- 이미 별 조각 장식이 있으면 추가 제작하지 않습니다.
- 제작 시 EXP 250을 소모합니다.
- labExpSpent가 250 증가합니다.
- 별 조각 장식이 추가됩니다.

### 12.3 기획 의도

별 조각은 즉시 성장과 장기 준비 사이의 선택을 만듭니다.

사용자 질문:

- 지금 레벨업을 위해 경험치를 유지할 것인가?
- 장기 성취를 위해 별 조각을 만들 것인가?

현재 구현은 단순하지만, 향후 별 투자 트리와 연결할 수 있는 기반입니다.

## 13. 마스터리 시스템

### 13.1 역할

마스터리는 사용자의 누적 성장을 압축해서 보여주는 고레벨 지표입니다. 레벨은 현재 생애의 성장이고, 마스터리는 전체 여정을 나타냅니다.

### 13.2 계산 원칙

현재 마스터리 랭크는 누적 획득 경험치와 별 수를 기반으로 계산됩니다.

의미:

- 많이 활동할수록 증가합니다.
- 환생 별이 마스터리에 반영됩니다.
- 현재 레벨이 낮아도 오래 사용한 흔적이 남습니다.

### 13.3 UX 목적

마스터리는 고레벨 사용자에게 다음 감각을 줍니다.

- 나는 오래 사용했습니다.
- 여러 생애의 성장이 합쳐져 있습니다.
- 레벨 초기화 후에도 내 계정의 깊이는 남습니다.

## 14. 주간 회고 시스템

### 14.1 역할

주간 회고는 사용자의 개발 성향을 서사적으로 요약합니다. 단순 통계보다 "이번 주 나는 어떤 개발자였나"를 보여주는 시스템입니다.

### 14.2 생성 규칙

활동이 발생하면 현재 주차를 계산합니다. 해당 주차의 회고가 없으면 dominant style을 기반으로 회고를 생성합니다.

회고 타입:

- 출하 중심의 주
- 리팩터 중심의 주
- 디버그 중심의 주
- 지식 축적의 주
- 지속성의 주

### 14.3 기획 의도

주간 회고는 단기 보상과 장기 자기 인식을 연결합니다.

좋은 회고:

- 평가하지 않습니다.
- 사용자의 강한 패턴을 보여줍니다.
- 다음 주 목표를 상상하게 합니다.

## 15. 환생 시스템

### 15.1 역할

환생은 장기 게임 루프의 핵심입니다. 레벨업이 끝나는 순간을 이탈 지점이 아니라 새로운 시작점으로 바꿉니다.

### 15.2 환생 조건

현재 조건:

- 레벨 30 이상
- 단계가 ultimate
- 생명 상태가 alive

사망 상태에서는 환생할 수 없습니다.

### 15.3 환생 보상

환생 시 획득 별:

- 기본 1개
- 30레벨 초과 20레벨마다 추가 1개

예:

- 30레벨: 별 1개
- 50레벨: 별 2개
- 70레벨: 별 3개

### 15.4 환생 후 초기화

환생 후 변경:

- 레벨 1
- 경험치 0
- 배고픔 15
- 기분 상승
- 에너지 상승
- 건강 100
- 진화 egg
- 단계 egg
- 계열 초기화
- 전문성 초기화
- 스타일 점수 일부 보존
- 카운터 초기화
- 스킬 초기화
- activeRaid 제거

보존:

- 환생 횟수
- 별
- 마스터리 일부
- 장식과 장기 기록

### 15.5 기획 의도

환생은 손실과 보상의 균형입니다. 모든 것이 유지되면 새 시작의 의미가 없고, 모든 것이 사라지면 사용자가 허탈해집니다. 따라서 현재 생애의 많은 요소는 초기화하되, 별과 일부 스타일 흔적은 남깁니다.

## 16. 로그와 성취 피드백

### 16.1 역할

로그는 시스템 계산의 결과를 사용자에게 설명합니다. 최신 성취 배너는 감정적 피드백이고, 로그는 증거입니다.

### 16.2 로그 구성

로그 항목:

- 메시지
- 경험치 변화
- 발생 시각
- breakdown
- 사용자 메시지 목록

### 16.3 breakdown 역할

breakdown은 성취 배너와 상세 메시지의 근거입니다.

예:

- quest.bugHunt
- combo.stabilizer
- raid.damage.releaseGolem
- raid.defeat.releaseGolem
- reincarnation

### 16.4 UX 원칙

사용자는 로그를 보고 왜 보상을 받았는지 이해할 수 있어야 합니다. 보상은 신뢰가 중요합니다. 이유를 모르는 보상은 처음에는 즐겁지만, 장기적으로 시스템을 불투명하게 만듭니다.

## 17. 밸런스 원칙

### 17.1 초반

초반 사용자는 빠른 보상이 필요합니다.

목표:

- 첫날 퀘스트 완료 가능
- 2레벨 빠른 도달
- 펫 반응 즉시 체감

### 17.2 중반

중반 사용자는 선택과 목표가 필요합니다.

목표:

- 퀘스트를 고릅니다.
- 직업을 선택합니다.
- 레이드를 시작합니다.
- 스타일 점수 차이를 확인합니다.

### 17.3 후반

후반 사용자는 장기 보상이 필요합니다.

목표:

- 레이드 클리어
- 시즌 milestone
- 마스터리 상승
- 환생 준비

### 17.4 초고레벨

초고레벨 사용자는 영구 기록이 필요합니다.

목표:

- 별 누적
- 환생 반복
- 장식 수집
- 시즌 기록

## 18. 악용 방지와 공정성

### 18.1 악용 가능성

개발 도구 기반 게임화는 다음 악용 가능성이 있습니다.

- 의미 없는 파일 변경 반복
- 빈 커밋 반복
- 진단 상태 조작
- 패키지 파일 무의미 변경

### 18.2 완화 원칙

현재 시스템은 완전한 부정행위 방지보다 보상 상한과 일일 제한을 통해 완화합니다.

완화 방식:

- 퀘스트는 하루 1회 완료
- 콤보는 최초 발견 중심
- 레이드 타격 보너스 상한
- 장식 중복 방지
- 시즌 milestone 중복 방지

향후 개선:

- 같은 파일 반복 변경 감쇠
- 커밋 간 최소 변화량 기준
- 특정 이벤트 반복 보상 감소
- 프로젝트별 보상 상한

## 19. 시스템 간 연결

### 19.1 퀘스트와 장식

퀘스트는 장식 수집과 연결됩니다. 사용자는 퀘스트를 단순 경험치 수단이 아니라 컬렉션 수단으로 인식합니다.

### 19.2 직업과 레이드

직업은 현재 경험치 보너스로 연결되지만, 향후 레이드 상성과 연결하기 좋습니다.

### 19.3 레이드와 시즌

레이드 보너스는 시즌 진행에 반영됩니다. 따라서 레이드 공략은 개인 성취와 시즌 성취를 동시에 밀어줍니다.

### 19.4 환생과 직업

별은 직업 보너스에 반영됩니다. 환생을 많이 한 사용자는 같은 직업 플레이에서도 더 나은 효율을 얻습니다.

### 19.5 스타일과 회고

- 개발 행동이 경험치로 변환됩니다.
- 오늘의 퀘스트를 선택할 수 있습니다.

- 레이드 보스를 시작할 수 있습니다.
- 레이드 피해와 클리어가 계산됩니다.
- 시즌 진행률이 증가합니다.
- 시즌 milestone 보상이 중복 지급되지 않습니다.
- 별 조각 제작 조건이 적용됩니다.
- 환생 조건이 정확합니다.
- 환생 후 별이 지급되고 상태가 초기화됩니다.
- 로그 breakdown이 최신 성취 배너와 연결됩니다.
- 전체 테스트가 통과합니다.

## 23. 최종 판단

Gitagotchi의 게임 시스템은 별도의 게임을 억지로 붙인 구조가 아니라, 개발 행동을 해석하는 규칙 집합이어야 합니다. 사용자가 한 diff, 커밋, 문제 해결, 문서화가 각각 성장, 퀘스트, 레이드, 시즌, 환생으로 연결될 때 앱은 단순한 장식에서 반복 사용 가능한 성장 시스템으로 바뀝니다.

이번 게임 시스템의 핵심은 다음과 같습니다.

- 오늘의 퀘스트는 매일의 시작 이유입니다.
- 장식은 행동의 흔적입니다.
- 직업은 플레이 스타일의 선언입니다.
- 콤보는 좋은 작업 흐름의 발견입니다.
- 레이드는 고레벨 사용자의 공략 목표입니다.
- 시즌은 반복 사용의 달력입니다.
- 연구소는 단기 경험치를 장기 자원으로 바꿉니다.
- 환생과 별은 사라지지 않는 성취입니다.

이 구조가 안정적으로 작동하면 Gitagotchi는 "코딩하면 숫자가 오르는 확장"이 아니라 "내 개발 루틴이 하나의 작은 RPG로 기록되는 확장"이 됩니다.
