# Gitagotchi 대격변 업데이트 제품 기획서

## 0. 문서 목적

이 문서는 Gitagotchi를 "커밋하면 펫이 자라는 귀여운 확장"에서 "개발자의 반복 루틴을 장기 성장 게임으로 바꾸는 엔드게임형 VS Code 확장"으로 전환하기 위한 제품 기획서입니다. 단순히 추가 기능 목록을 나열하는 문서가 아니라, 사용자가 왜 매일 돌아와야 하는지, 고레벨 사용자가 왜 계속 붙잡혀야 하는지, 어떤 시스템이 어떤 감정과 행동을 만들지까지 정의합니다.

이번 업데이트는 작은 편의 개선이 아닙니다. 제품의 중심 루프를 다시 짜는 업데이트입니다. 기존 Gitagotchi의 핵심인 "개발 행동이 펫 성장으로 이어진다"는 아이디어는 유지하되, 성장 이후의 목표, 선택, 수집, 도전, 회고, 자랑할 만한 기록을 추가해 앱의 체류 동기를 바꿉니다.

## 1. 현재 제품 진단

### 1.1 현재 Gitagotchi의 강점

Gitagotchi의 강점은 매우 명확합니다. 개발자가 이미 하고 있는 행동을 별도의 수동 입력 없이 펫 성장으로 전환합니다. 사용자는 새로운 습관을 배울 필요 없이 평소처럼 코드를 작성하고 커밋하고 프로젝트를 진행하면 됩니다. 이 점은 개발 도구 확장으로서 매우 중요합니다. 업무 흐름을 방해하지 않고, 사용자의 실제 성취를 가볍게 시각화합니다.

또한 펫이라는 대상은 감정적 연결을 만들기 좋습니다. 레벨, 경험치, 진화, 상태 표시 같은 요소는 빠르게 이해되고, 사용자가 자신의 활동을 조금 더 개인적인 방식으로 받아들이게 만듭니다.

### 1.2 현재 Gitagotchi의 한계

문제는 성장의 깊이입니다. 펫이 자라는 것만으로는 초반에는 재미있지만, 일정 시간이 지나면 "그래서 이제 무엇을 하지?"라는 질문이 생깁니다. 특히 고레벨 사용자는 레벨업 속도가 느려지고, 새로 확인할 변화가 줄어들며, 앱을 열어야 할 명확한 이유를 잃습니다.

현재 경험에서 부족한 요소는 다음과 같습니다.

- 오늘 반드시 확인해야 하는 목표가 약합니다.
- 고레벨 이후의 장기 목표가 부족합니다.
- 사용자의 선택이 성장 방향을 바꾼다는 느낌이 약합니다.
- 큰 성취가 발생해도 화면에서 충분히 크게 느껴지지 않습니다.
- 매일의 작은 개발 행동이 장기 서사로 연결되지 않습니다.
- 수집, 도전, 회고, 기록 같은 반복 동기가 약합니다.

### 1.3 핵심 문제 문장

Gitagotchi는 "성장한다"는 사실은 보여주지만, "내가 지금 무엇을 공략하고 있으며, 다음에 무엇을 얻고 싶고, 오래 한 사람만 가질 수 있는 무엇이 남는지"를 충분히 제공하지 못합니다.

## 2. 제품 비전

Gitagotchi의 다음 단계는 개발자용 성장 RPG입니다. 여기서 RPG는 사용자가 별도 게임을 플레이해야 한다는 뜻이 아닙니다. 사용자가 이미 하고 있는 개발 행동이 퀘스트, 레이드, 시즌, 빌드, 연구, 환생으로 번역된다는 뜻입니다.

새로운 Gitagotchi는 다음 질문에 답해야 합니다.

- 오늘 앱을 열면 무엇을 해야 하는가?
- 이번 주에 달성할 목표는 무엇인가?
- 고레벨 사용자는 어떤 난도 높은 목표를 공략하는가?
- 오래 사용한 사람만 보여줄 수 있는 기록은 무엇인가?
- 지금 한 개발 행동이 어떤 게임적 의미를 가지는가?
- 다음 성장까지 얼마나 남았고, 그 성장은 왜 기대되는가?

## 3. 타깃 사용자와 동기 구조

### 3.1 신규 사용자

신규 사용자는 복잡한 시스템을 먼저 원하지 않습니다. 이 사용자는 "아, 내가 코딩하면 이 펫이 반응하는구나"를 빠르게 이해해야 합니다. 따라서 첫 경험은 오늘의 퀘스트, 펫 상태, 작은 보상에 집중합니다.

신규 사용자에게 필요한 감정은 다음과 같습니다.

- 이해하기 쉽다.
- 귀엽고 즉각적이다.
- 내가 방금 한 행동이 반영된다.
- 다음에 한 번 더 열어보고 싶다.

### 3.2 반복 사용자

반복 사용자는 앱을 이미 이해한 사람입니다. 이 사용자는 단순한 레벨업보다 "오늘의 목표", "연속 행동", "이번 시즌 진행률" 같은 구조가 필요합니다. 매일 확인할 이유가 있어야 하고, 하루를 놓쳐도 다시 시작하기 쉬워야 합니다.

반복 사용자에게 필요한 감정은 다음과 같습니다.

- 오늘 할 일이 보인다.
- 조금씩 누적되는 느낌이 있다.
- 내 개발 리듬이 앱에 반영된다.
- 짧게 확인해도 보상이 있다.

### 3.3 고레벨 사용자

고레벨 사용자는 가장 중요한 대상입니다. 이 사용자는 이미 기본 성장 루프를 지나왔고, 단순 경험치 보상만으로는 충분하지 않습니다. 이들에게는 공략, 최적화, 수집, 영구 성장, 희귀 기록이 필요합니다.

고레벨 사용자에게 필요한 감정은 다음과 같습니다.

- 내가 오래 했기 때문에 가능한 목표가 있다.
- 내 성장 방식이 다른 사람과 다르다.
- 어려운 보스를 공략하고 있다는 긴장감이 있다.
- 환생해도 남는 영구 성취가 있다.
- 다음 시즌에도 돌아올 이유가 있다.

## 4. 대격변 업데이트의 핵심 루프

이번 업데이트의 핵심 루프는 다음과 같습니다.

1. 사용자가 VS Code에서 평소처럼 개발합니다.
2. 개발 행동이 경험치, 퀘스트 진행, 콤보, 레이드 피해량으로 변환됩니다.
3. 오늘의 퀘스트와 시즌 진행률이 단기 목표를 제공합니다.
4. 레이드, 연구소, 직업 빌드가 중기 목표를 제공합니다.
5. 환생과 별이 장기 목표를 제공합니다.
6. 중요한 순간은 패널 상단 배너, 보스 아레나, 별 궤도로 즉시 시각화됩니다.
7. 사용자는 다음 목표를 확인하고 다시 개발 행동으로 돌아갑니다.

이 루프에서 중요한 점은 사용자가 게임을 따로 해야 하는 것이 아니라는 점입니다. Gitagotchi는 개발 행동을 방해하지 않고, 그 행동의 의미를 게임적으로 번역합니다.

## 5. 시스템 설계

### 5.1 오늘의 퀘스트

오늘의 퀘스트는 매일 앱을 열 이유를 만드는 가장 앞단의 시스템입니다. 목표는 어렵지 않아야 하고, 사용자의 실제 개발 행동으로 자연스럽게 완료되어야 합니다.

기획 의도:

- 사용자가 매일 확인할 첫 번째 목표를 제공합니다.
- 짧은 세션에서도 완료 가능한 보상을 제공합니다.
- 장기 시스템을 처음부터 모두 이해하지 않아도 재미를 느끼게 합니다.

사용자 경험:

- 패널에서 오늘의 퀘스트를 확인합니다.
- 개발 행동을 하면 퀘스트가 진행됩니다.
- 완료 시 경험치와 장식 보상을 얻습니다.
- 완료 순간은 배너와 로그로 확인됩니다.

고레벨 확장성:

- 시즌 한정 퀘스트
- 직업별 전용 퀘스트
- 레이드 보스 약점과 연결된 퀘스트
- 주간 연속 완료 보상

구현 근거:

- `src/core/questEngine.ts`
- `src/core/petState.ts`
- `tests/questEngine.test.ts`

### 5.2 직업과 빌드

직업과 빌드는 고레벨 사용자가 자신의 플레이 스타일을 해석하는 시스템입니다. Gitagotchi는 단순히 레벨만 보여주지 않고, 사용자의 개발 행동 패턴이 어떤 성향으로 쌓이는지 보여줘야 합니다.

기획 의도:

- 사용자의 개발 방식에 정체성을 부여합니다.
- 같은 레벨의 사용자도 서로 다른 빌드를 갖게 합니다.
- 향후 레이드 보너스, 연구소 제작, 시즌 칭호와 연결할 수 있습니다.

예상 직업 방향:

- 릴리즈형: 배포, 마감, 완성 중심의 사용자
- 리팩터형: 구조 개선과 유지보수 중심의 사용자
- 탐험형: 여러 파일과 기능을 넓게 다루는 사용자
- 수호형: 테스트, 안정성, 버그 수정 중심의 사용자

사용자 경험:

- 패널에서 현재 빌드 성향을 확인합니다.
- 개발 행동이 특정 성향 점수로 누적됩니다.
- 일정 기준을 넘으면 직업 또는 랭크가 강화됩니다.
- 직업은 레이드와 시즌 보상에서 의미를 갖습니다.

구현 근거:

- `src/core/endgameEngine.ts`
- `src/ui/petPanelPresentation.ts`
- `tests/endgameEngine.test.ts`

### 5.3 레이드 보스

레이드는 고레벨 사용자를 위한 핵심 엔드게임입니다. 경험치가 오르는 것만으로는 부족한 시점에 "현재 공략 중인 적"을 제공합니다. 보스 체력은 장기 진행도를 만들고, 타격 순간은 즉각적인 만족감을 만듭니다.

기획 의도:

- 고레벨 사용자가 반복적으로 공략할 목표를 제공합니다.
- 매일의 개발 행동이 보스 체력 감소로 전환됩니다.
- 격파 기록이 누적되어 장기 성취가 됩니다.

보스 설계 원칙:

- 보스는 개발자의 실제 어려움을 은유해야 합니다.
- 각 보스는 이름, 체력, 진행률, 시각 실루엣을 가져야 합니다.
- 격파는 강하게 표시되어야 하고, 다음 목표로 자연스럽게 이어져야 합니다.

현재 적용된 보스 방향:

- 레거시 드래곤: 오래된 구조와 기술 부채를 상징합니다.
- 버그 로드: 반복적으로 나타나는 오류와 회귀를 상징합니다.
- 릴리즈 골렘: 배포와 마감의 무게를 상징합니다.
- 의존성 망령: 라이브러리, 버전, 환경 문제를 상징합니다.

사용자 경험:

- 사용자는 현재 레이드 보스와 체력을 확인합니다.
- 개발 행동이 보스 피해량으로 환산됩니다.
- 피해가 들어가면 레이드 히트 배너가 표시됩니다.
- 보스 체력이 0이 되면 레이드 클리어 배너가 표시됩니다.
- 격파 수는 누적 기록으로 남습니다.

구현 근거:

- `src/core/endgameEngine.ts`
- `src/ui/petPanelPresentation.ts`
- `tests/endgameEngine.test.ts`
- `tests/petPanel.test.ts`

### 5.4 시즌 진행도

시즌은 반복 사용의 달력을 만듭니다. 사용자는 매일의 작은 활동이 이번 시즌의 보상으로 연결된다는 느낌을 받아야 합니다.

기획 의도:

- 단기 행동을 기간제 목표로 묶습니다.
- 장기 사용자에게 다음 시즌 복귀 동기를 제공합니다.
- 이벤트, 한정 장식, 시즌 보스 확장의 기반이 됩니다.

사용자 경험:

- 현재 시즌 진행률을 확인합니다.
- 매일의 퀘스트, 콤보, 레이드 행동이 시즌 점수로 연결됩니다.
- 시즌 종료 시 회고와 보상을 받을 수 있습니다.

운영 확장성:

- 시즌별 테마
- 시즌 한정 보스
- 시즌 한정 장식
- 시즌별 칭호
- 시즌 회고 카드

구현 근거:

- `src/core/endgameEngine.ts`
- `src/ui/petPanelPresentation.ts`

### 5.5 연구소와 별 조각

연구소는 고레벨 자원 시스템입니다. 사용자는 단순히 경험치를 얻는 것이 아니라, 장기 성장 재료를 모으고 제작하는 감각을 가져야 합니다.

기획 의도:

- 고레벨 이후에도 자원 사용 목표를 제공합니다.
- 환생과 연결되는 영구 성장의 재료를 제공합니다.
- 반복 행동에 장기 투자 의미를 부여합니다.

사용자 경험:

- 개발 활동을 통해 연구 재료 또는 별 조각을 얻습니다.
- 일정 수량을 모으면 제작하거나 성장에 사용합니다.
- 제작 결과는 환생, 별, 장식, 보너스와 연결됩니다.

고레벨 확장성:

- 별 투자 트리
- 직업별 연구 보너스
- 레이드 보스별 희귀 재료
- 시즌 한정 연구식

구현 근거:

- `src/core/endgameEngine.ts`
- `src/ui/petPanelPresentation.ts`

### 5.6 콤보와 마스터리

콤보는 사용자의 연속 행동을 즉시 보상하는 시스템입니다. 마스터리는 장기 누적을 보여주는 시스템입니다. 두 시스템은 각각 짧은 만족감과 긴 자부심을 담당합니다.

기획 의도:

- 개발자의 꾸준한 리듬을 보상합니다.
- 단발성 큰 작업만이 아니라 반복적인 작은 행동도 가치 있게 만듭니다.
- 패널에서 "방금 잘했다"는 느낌을 줍니다.

사용자 경험:

- 긍정적인 개발 행동이 연속되면 콤보가 쌓입니다.
- 콤보가 발생하면 순간 배너가 표시됩니다.
- 누적된 성취는 마스터리 랭크로 표현됩니다.

구현 근거:

- `src/core/endgameEngine.ts`
- `src/core/growthEngine.ts`
- `src/ui/petPanelPresentation.ts`

### 5.7 환생과 별

환생은 고레벨 사용자의 가장 강한 장기 목표입니다. 레벨업이 끝나는 순간이 이탈 지점이 아니라 새로운 시작점이 되어야 합니다. 환생 별은 사용자가 오래 플레이했다는 증거로 남습니다.

기획 의도:

- 레벨 상한 이후에도 계속 성장할 이유를 제공합니다.
- 초기화의 손실감을 영구 보상으로 상쇄합니다.
- 고레벨 사용자가 반복 루프를 자발적으로 선택하게 합니다.

사용자 경험:

- 충분히 성장하면 환생 조건을 만족합니다.
- 환생 시 별을 획득합니다.
- 별은 패널의 별 궤도에 표시됩니다.
- 환생 후에도 영구 성취는 남습니다.

감정 설계:

- 환생은 단순 초기화가 아니라 졸업식이어야 합니다.
- 별은 수치가 아니라 오래 사용한 흔적이어야 합니다.
- 화면에서는 별 궤도로 즉시 보이게 해야 합니다.

## 6. 정보 구조와 화면 우선순위

Gitagotchi 패널은 복잡한 게임 UI가 되어서는 안 됩니다. VS Code 안에서 빠르게 훑어볼 수 있어야 합니다. 따라서 화면 우선순위는 다음과 같습니다.

1. 최신 성취 순간
2. 현재 펫과 핵심 상태
3. 오늘의 목표
4. 레이드 또는 엔드게임 진행
5. 시즌, 연구, 마스터리, 환생 정보
6. 로그와 상세 기록

이 우선순위는 신규 사용자와 고레벨 사용자를 동시에 만족시키기 위한 구조입니다. 신규 사용자는 펫과 오늘의 목표를 먼저 보고, 고레벨 사용자는 레이드와 별, 시즌 진행을 이어서 확인합니다.

## 7. 사용 시나리오

### 7.1 신규 사용자의 첫날

사용자는 VS Code에서 Gitagotchi 패널을 엽니다. 화면에는 펫과 오늘의 퀘스트가 보입니다. 사용자는 별도 조작 없이 평소처럼 코드를 작성합니다. 잠시 후 퀘스트가 완료되고, 패널 상단에 성취 배너가 나타납니다. 사용자는 "내 개발 행동이 실제로 반영되는구나"를 이해합니다.

성공 조건:

- 첫날에 최소 하나의 보상을 경험합니다.
- 복잡한 엔드게임 설명 없이도 재미를 이해합니다.
- 다음 날 다시 확인할 이유를 얻습니다.

### 7.2 반복 사용자의 평일 루틴

사용자는 하루를 시작하며 패널을 확인합니다. 오늘의 퀘스트와 시즌 진행률을 봅니다. 작업을 하며 콤보가 쌓이고, 퀘스트가 완료됩니다. 시즌 점수가 조금 올라가고 장식 또는 연구 재료가 누적됩니다.

성공 조건:

- 매일 30초 안에 오늘의 목표를 파악합니다.
- 개발 행동 후 보상 변화가 보입니다.
- 하루를 놓쳐도 다시 이어갈 수 있습니다.

### 7.3 고레벨 사용자의 레이드 세션

고레벨 사용자는 현재 레이드 보스의 남은 체력을 확인합니다. 오늘 작업을 통해 보스에게 피해를 줍니다. 패널 상단에 레이드 히트 배너가 표시되고, 보스 체력바가 줄어듭니다. 며칠간 누적된 피해 끝에 보스를 격파하면 클리어 배너와 격파 기록이 남습니다.

성공 조건:

- 보스 체력이 줄어드는 장기 목표가 보입니다.
- 타격 순간이 즉시 느껴집니다.
- 격파 기록이 다음 목표로 이어집니다.

### 7.4 초고레벨 사용자의 환생 루프

사용자는 충분한 성장과 자원을 모은 뒤 환생을 선택하거나 환생 조건을 만족합니다. 레벨 루프는 다시 시작되지만 별은 남습니다. 패널의 별 궤도는 사용자가 얼마나 오래 플레이했는지 보여줍니다. 사용자는 다음 환생, 더 높은 별 수, 더 어려운 보스를 목표로 삼습니다.

성공 조건:

- 초기화가 손실이 아니라 명예처럼 느껴집니다.
- 별이 즉시 보이고 누적됩니다.
- 환생 이후에도 다음 목표가 명확합니다.

## 8. 고레벨 유저 리텐션 전략

고레벨 사용자는 단순 보상보다 "내가 오래 했기 때문에 가능한 일"을 원합니다. 이번 업데이트의 리텐션 전략은 다섯 축으로 구성됩니다.

### 8.1 공략

레이드 보스는 공략 대상입니다. 사용자는 체력을 깎고, 격파 기록을 쌓고, 다음 보스를 준비합니다.

### 8.2 최적화

직업과 빌드는 사용자의 개발 패턴을 해석합니다. 향후에는 직업별 보너스와 레이드 상성을 붙여 최적화 재미를 강화할 수 있습니다.

### 8.3 수집

장식, 별, 시즌 보상, 보스 격파 기록은 수집 대상입니다. 수집은 장기 사용의 가장 안정적인 동기입니다.

### 8.4 영구 성장

환생 별은 초기화 이후에도 남습니다. 고레벨 사용자는 "사라지지 않는 성장" 때문에 다음 루프를 시작할 수 있습니다.

### 8.5 기록과 회고

주간 회고와 시즌 기록은 사용자의 개발 여정을 돌아보게 합니다. 단순 생산성 통계가 아니라 Gitagotchi의 성장 서사로 보여주는 것이 중요합니다.

## 9. 경쟁 제품 관점의 차별화

일반 생산성 도구는 사용량, 시간, 작업 수를 보여줍니다. 일반 게임화 도구는 배지와 점수를 제공합니다. Gitagotchi의 차별점은 개발자의 실제 작업 맥락을 펫 성장 RPG로 변환한다는 점입니다.

차별화 포인트:

- 개발 행동 기반 자동 진행
- 펫과 엔드게임의 결합
- 레이드와 환생을 통한 고레벨 목표
- VS Code 내부에서 가볍게 확인 가능한 구조
- 개발자의 성장 기록을 감정적 대상으로 시각화

Gitagotchi가 지향해야 할 포지션은 "생산성 통계 도구"가 아니라 "개발 루틴에 붙어 있는 작은 성장 세계"입니다.
